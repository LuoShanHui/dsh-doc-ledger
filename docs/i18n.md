# i18n 现状

**已实施完整双语（zh / en）。** 本文档记录最终形态；实施路线与取舍见 [i18n-plan.md](i18n-plan.md)，
原始中文串清单见 [i18n-strings.md](i18n-strings.md)。

## 字典

`src/client/10-locale.js` 里 `zh` / `en` 两个字典，按功能分组，**159 个 key 一一对应**：

```
tab.*  guide.*  category.*  encoding.*  search.*  row.*  section.*  sort.*
frame.*  toast.*  export.*  toolbar.*  menu.*  preview.*  summary.*
empty.*  filter.*  expand.*
```

组合句不再拼接中文碎片，而是整句 + `{占位符}`，例如
`t("preview.truncated", { shown, total })`、`t("summary.line", { sessions, used, ... })`。
这样英文语序可以自由安排，不受中文词序限制。

## 运行时

`src/client/05-runtime.js` 提供全 bundle 共用的 `t(key, params)`：

- `apply()` 里 `setFallback(zh)` + `setTranslator(ctx.locale.bind(NS))`；
- 求值期常量表（`CATEGORY_LABEL`、排序键数组）**存 key 不存中文**，在渲染时经 `t()` 解析，
  所以切换语言不会把中文冻死；
- `{name}` 插值在本插件内完成，不依赖宿主 `locale` 是否支持参数；
- 没有宿主 locale 服务时（静态报告、早期渲染）回退到中文兜底，绝不把裸 `a.b.c` key 显示给用户。

## 验证

| 层 | 工具 | 断言 |
|---|---|---|
| 静态 | `tools/i18n-check.mjs`（在 `npm test` / CI 中） | zh/en 键集合一致、无空值/TODO、所有 `t()` 引用有 key、字典无死条目、占位符集合一致 |
| UI | `npm run harness` + `?locale=en` / `?locale=zh` | 双语言各渲染一遍，检查无裸 key、无 UI 中文残留（数据里的中文文件名/会话标题保留） |

`tools/i18n-extract.mjs` 可从源码重新生成中文串清单，用于审计「还有没有漏网的硬编码文案」。

## 不翻译的内容

- 会话标题、文件名、路径、程序名等**用户数据**；
- `130-apply.js` 里命令面板的中文搜索别名（`文档`、`文档台账`）——它们是让用户能用中文搜到
  这个 tab 的关键词，不是界面文案。

## 已知取舍

- 复数暂用简化式（`Files: {n}` 风格的固定句式），没有接入 `Intl.PluralRules`；
- 数值单位 / 日期格式沿用宿主与 `fmtTime`，未做 locale 化；
- 文档（README、Release notes、SECURITY）仍是中文为主 + 英文摘要。
