# v0.6.0 · 三行类型筛选，和三类静默丢数据

[English](release-v0.6.0.en.md) · **中文**

这个版本有两件事：把类型筛选从弹出式树改成三行内联（顺带解决了它一直不可键盘操作的问题），
以及修掉引擎里三处**不报错、但会静默丢掉数据**的缺陷。

## 类型筛选：三行，互斥，并集

上一版的弹出式树有两个问题：二级藏在一次点击之后，以及**键盘完全不可用**——面板里所有行
都是 `tabIndex: -1` 且没有 `onKeyDown`，能打开、能看见，但选不了任何一项。

现在是三行：

| 行 | 内容 | 行为 |
|---|---|---|
| 1 | 所有一级类型 + 「已删除」 | 平铺、可换行、多选 |
| 2 | 已选家族的扩展名 | 多选，**可跨家族** |
| 3 | 已勾选项 + `✕ 清除筛选` | 每项带 `×` 单独移除 |

三条规则收在 `typeFilterOf` 一个构造器里，任何一次状态变化都经过它：

- **同家族互斥**：勾「代码」清掉 `code/*`，勾 `code/java` 取消「代码」。「全部」和「其中一部分」
  是两种意思，同时勾选会得到一个解释不清的筛选。别的家族不受影响——这正是 `code/java` 与
  `config/yml` 能共存的原因。
- **结果是并集**：勾两个一级会同时列出两类文件。交集在勾第二个家族时就永远是空集了。
- **`""` 是真实取值**：它表示「无扩展名的文件」，不是「没有选择」。

## 三处静默丢数据

### 1. 路径拼接吞掉写入

扫描器检查了字符串**后面**是否跟 `+`，却没检查前面。于是 `process.cwd() + "/lib/ledger.js"`
的右半截被当成一个独立文档记录下来：

```js
const mod = await import(pathToFileURL(process.cwd() + "/lib/ledger.js").href);
// → 台账里多出一行「/lib/ledger.js」，无法预览、无法打开
```

全库 717 条 literal 派生记录里，55 条解析成非绝对路径；132 条仅由 literal 支撑的行中，
**63 条磁盘上根本不存在**。补齐对称检查后幽灵行 17 → 0，没有误伤任何真实记录。

### 2. 路径前缀被压平

`resolvePath` 把路径拆成段再拼回去，前缀就丢了：

| 输入 | 改前 | 改后 |
|---|---|---|
| `\\server\share\x.md` | `server\share\x.md` | `\\server\share\x.md` |
| `/abs/x.md` | `abs\x.md` | `D:\abs\x.md` |

这不只是难看：退化成裸文件名后，它可能**恰好命中工作目录里的真实文件**，让一个不相干的
文档冒充被打开的那个。现在按 UNC / 盘符 / 根路径 / 相对路径四种形状分别处理，
`..` 也不能越过锚点。

### 3. 引擎指纹不认识扫描规则

`ENGINE_FINGERPRINT` 只哈希分类表和引擎号。所以修完上面两个缺陷后，**用户看到的仍是旧数据**
——缓存没有失效，要等有人手动改引擎号。

现在把 `lib/ledger.js` 的内容哈希并入指纹。这个缺口是实测撞出来的：修完扫描器后幽灵行
依然在屏幕上，直到手动 bump。

## 其余的 UI 缺陷

- **「已删除」计数与行数不一致**：计数按全量累加，列表走筛选条件。真实台账上 20 种筛选组合
  里 18 种不一致——芯片恒显示 548，而实际行数在 0~210 之间。现在两者共用一个条件集。
- **开关状态被自己的计数绑住**：`aria-pressed` 原本跟着计数走，于是「已删除」在一个不含
  已删除文件的类型下会显示 0、看起来像关掉了。现在开关只看自身状态，数字只是信息。
- **搜索高亮从不渲染**：`highlight()` 一直是对的，但 `Section` 读的 `props.query` 没有任何人传。
  这次没有去补传参，而是**删掉了第二条通道**——查询词只存在于 `conditions` 里，
  和当初把筛选条件收敛成单一对象是同一个道理。
- **高亮在大小写长度变化的字符上错位**：`İ` 小写后是两个码元，拿降维后的下标切原串就会偏。
  `doc-İstanbul-notes.md` 搜 `notes` 会高亮成 `otes.`。现在逐码元折叠并保留回映射表。

## 测试

128 → 139 项。除了覆盖上面每条缺陷的行为，另加**两条结构性守卫**——因为这一轮的教训
不只是"某个函数错了"，而是"函数对但没人调用"：

1. 被测的每个纯函数必须在 `client.js` 里至少有一个调用点。`extensionChips` 曾有 4 条断言全绿，
   而重构后它在 UI 里**没有任何调用方**，测试提供了虚假的安全感。
2. 查询词不得存在第二条通道。`props.query` 一旦回到代码里，说明通道又分叉了。

另外 **harness 现在离线可用**：React 18 UMD 固化进 `tools/harness/vendor/`。它是验证 UI 的
唯一手段，此前却依赖 unpkg 重定向，无网机器直接白屏。
